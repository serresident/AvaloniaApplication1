## 1. Overview & Архитектурный контекст

Проектирование мнемосхем HMI/SCADA в режиме редактирования (`IsDesignMode = true`) сопряжено с риском ошибочных изменений топологии, случайного удаления элементов или сбоя настроек.

Целевое решение предоставляет полноценный механизм безопасного редактирования с возможностью пошаговой отмены, повтора и визуального перехода во времени:
1. **Time-Travel Side Panel:** Выдвижная боковая шторка (Drawer 280px) со списком выполненных действий, временными метками и кликабельной навигацией по истории.
2. **Атомарный охват всех операций:** Отслеживание перемещения, ресайза, добавления/удаления, врезки труб, соосной сборки, а также сохранения свойств через диалоговые окна.
3. **Кольцевой стек на 30 шагов:** Буфер фиксированной глубины (FIFO/Ring buffer) с нулевым риском утечек памяти.
4. **Дифференциальное согласование (Reconciliation):** Обновление существующих ViewModels без пересоздания и без разрыва подписок на живую телеметрию.
5. **20-минутный таймер удержания истории в Runtime:** Защита контекста при кратковременном переключении режимов и авто-сброс памяти при длительном простое.

## 2. Результаты многолинзового аудита (Multi-Lens Swarm Findings)

### 🔴 Критический блокер: Отсутствие `Id` в `WidgetConfig` (`egm-codebase-details`)
* **Проблема:** В текущей модели `WidgetConfig` отсутствует уникальный идентификатор. Без него дифференциальное сопоставление виджетов между снимками невозможно.
* **Решение:**
  * В `WidgetConfig` добавляется: `public Guid Id { get; set; } = Guid.NewGuid();`.
  * В `WidgetViewModelBase` пробрасывается: `public Guid Id => OriginalConfig.Id;`.
  * При дублировании виджетов (`DuplicateWidget`) клону явно присваивается новый `clone.Id = Guid.NewGuid();`.

### 🟡 Защита от циклической фиксации (Reentrancy Guard) (`egm-implementation-readiness`)
* При применении снимка свойства виджетов меняются программно.
* В `DashboardViewModel` вводится флаг `_isReconciling`. Все обработчики `OnWidgetPropertyChanged` блокируют запись в историю, если `_isReconciling == true`.

### 🟡 Изоляция области действия (Per-Dashboard Scope) (`egm-zoom-out`)
* Приложение поддерживает вкладки «Дашборд» и «Мнемосхема».
* Экземпляр `IHistoryService` создается индивидуально для каждого `DashboardViewModel`, предотвращая взаимное разрушение истории между вкладками.

### 🟡 Дросселирование клавиатурного перемещения (Nudge Debouncing) (`egm-design`)
* Пошаговое смещение стрелками клавиатуры дросселируется таймером (400 мс). Координаты меняются плавно на лету, а снимок в историю фиксируется только после отпускания клавиши, предотвращая мгновенное исчерпание буфера из 30 шагов.

### 🟡 Эргономика боковой шторки (Collapsible Drawer) (`egm-design`)
* На экранах 1024×600 постоянная панель крадет 25% холста.
* Панель выполняется выдвижной (Flyout / Overlay Drawer) с кнопкой-тумблером в тулбаре `История (12)`.

## 3. Спецификация компонентов Clean Architecture

* **Domain Layer (`Models/History/`, `Models/Config/`):**
  * `WidgetConfig.Id`: Персистентный Guid виджета.
  * `HistoryStep`: Неизменяемая запись (`Guid Id`, `DateTime Timestamp`, `string Title`, `string IconKey`, `DashboardConfig Snapshot`).
  * `IHistoryService`: Контракт сервиса истории.
* **Application Layer (`Services/History/`):**
  * `HistoryService`: Кольцевой буфер `Capacity = 30`, отсечение будущих ветвей при ветвлении, 20-минутный таймер `Observable.Timer`.
* **Presentation Layer (`ViewModels/Panels/`, `Views/Panels/`):**
  * `DashboardViewModel.RestoreSnapshot(DashboardConfig snapshot)`: Дифференциальное обновление (Update существующих, Remove удаленных, Add новых).
  * `HistoryPanelViewModel`: Вьюмодель боковой панели.
  * `HistorySidePanel.axaml`: Разметка шторки таймлайна.

## 4. Goals vs. Non-Goals

* **In-Scope Goals:**
  * Кольцевой буфер на 30 шагов.
  * Горячие клавиши `Ctrl+Z`, `Ctrl+Y`, `Ctrl+Shift+Z`.
  * Кнопки Undo/Redo и вызов шторки истории в тулбаре мнемосхемы.
  * Прямой переход к любому шагу по клику в списке.
  * Фиксация операций холста и диалоговых окон.
  * 20-минутный таймер авто-сброса при неактивности в режиме Runtime.
* **Out-of-Scope Non-Goals:**
  * Сохранение стека истории на диск в файл `config.json` между перезапусками приложения.
  * Отмена действий оператора в режиме реального времени (ввод уставок, переключение тумблеров в Runtime).

## 5. Alternatives Weighed

| Альтернатива | Причина отклонения |
|---|---|
| **Командный паттерн (`IUndoableCommand`)** | Колоссальный риск багов и рассинхрона при сложных топологиях труб; требует десятков классов команд. |
| **Полный сброс и перезагрузка ViewModels** | Обрыв подписок на ПЛК, сброс таймеров, мерцание экрана. Заменен на дифференциальное согласование по `Id`. |
| **Постоянная боковая панель** | Занимает 25% рабочей области на компактных промышленных экранах. Заменена на выдвижную шторку. |
